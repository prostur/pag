Insieme.

Scopri come Git e GitHub aiutano a salvare le modifiche, sperimentare idee, collaborare e integrare il lavoro in un progetto comune. Segui gli schemi animati e prova il mini laboratorio.

La grande idea

Git registra la storia. GitHub connette le persone.

Git è un sistema di controllo versione: tiene traccia delle modifiche ai file nel tempo. GitHub è una piattaforma online che ospita repository Git e aggiunge strumenti per collaborare, discutere e revisionare il codice.

Git e GitHub non sono la stessa cosa

Git funziona sul computer e gestisce versioni, rami e unione delle modifiche. GitHub ospita repository Git online e offre pull request, issue, revisioni, permessi e automazioni.

Un progetto, tante possibilità

Puoi lavorare da solo, invitare collaboratori, proporre cambiamenti senza toccare subito il ramo principale e conservare una cronologia consultabile.

Sperimentare senza rischi

I branch sono linee di lavoro parallele

Un branch permette di sviluppare una funzione o correggere un errore senza modificare direttamente il ramo principale. Quando il lavoro è pronto, le modifiche possono essere unite con un merge.

main ramo principale feature/login ramo dedicato a una nuova funzione

Perché usare i branch?

✓
Isolamento

Il lavoro in corso non destabilizza main.

✓
Parallelismo

Più persone lavorano su attività diverse.

✓
Revisione

Il codice viene controllato prima dell'unione.

Merge: unire le storie

Il merge integra in un branch le modifiche sviluppate in un altro. Se due modifiche incompatibili toccano la stessa parte di un file, può verificarsi un conflitto: una persona deve decidere come combinarle.

Un conflitto non è un disastro

Git segnala le parti in contrasto. Si apre il file, si sceglie o si combina il contenuto corretto, si salva e si completa il merge con un nuovo commit.

Il lavoro di squadra

Pull request: una proposta, una conversazione

Una pull request (PR) propone di integrare le modifiche di un branch in un altro. Non è soltanto un pulsante di merge: è uno spazio per spiegare, discutere, rivedere e migliorare il codice.

Issues: organizzare il lavoro

Le issue descrivono problemi, idee, attività o richieste. Possono avere assegnatari, etichette, milestone e discussioni. Aiutano il team a capire cosa serve fare.

Actions: automatizzare

GitHub Actions può eseguire workflow automatici, per esempio testare il progetto quando viene aperta una pull request o pubblicare un sito dopo un aggiornamento.
